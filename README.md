# Minecraft-CTF

基于 Bukkit/Spigot 的 Capture The Flag (夺旗) 游戏模式插件，使用 [TabooLib 6.3.0](https://github.com/TabooLib/taboolib) 框架开发。Kotlin 2.3.20 编写，目标 JVM 17，适配 Minecraft 1.21。

## 游戏规则

### 队伍

两支队伍对战：LEFT（红队）和 RIGHT（蓝队）。玩家被组织为 Group（分组），匹配时以 Group 为单位分配到队伍。每局游戏的分组分配是随机的。

### 胜利条件

夺走对方旗帜并带回己方金块目标点上交。率先完成 8 次夺旗的队伍获胜。

每局限时 3 分钟。时间耗尽时，夺旗数多的一方获胜；双方持平则为平局。

### 旗帜机制

旗帜是放置在铜块（Waxed Copper Block）和橡木栅栏（Oak Fence）杆上的彩色旗帜。红队在左半场放置红色旗帜，蓝队在右半场放置蓝色旗帜。

**拾取**：走到对方旗帜附近（检测玩家脚下方块及其前后左右各 1 格范围内）会自动拾取，旗帜出现在头盔槽位。拾取时原旗帜结构（铜块变为草方块，栅栏和旗帜消失）被移除。头盔槽位必须为空才能拾取。

**上交**：带着对方旗帜站在己方半场的金块目标点上方即可完成一次夺旗。上交要求金块上方两层均为空气。旗帜会被重新放置在金块上（栅栏 + 旗帜），玩家头盔槽位清空。

**掉落**：如果携带旗帜的玩家死亡或被抓住，旗帜会以玩家为中心螺旋向外搜索（最大 20 格范围）一个有效掉落位置。有效位置需要满足：位于场地内、草方块上方、上方两层均为空气。找到后在该位置重新生成旗帜结构（铜块 + 栅栏 + 旗帜）。

### 抓捕

当双方玩家（均未处于寄生状态）距离小于 0.5 格（x/z 平面）且高度差小于 1 格时触发抓捕判定：

- 在己方半场：你抓住入侵者，对方丢弃旗帜并被传送到你方的监狱
- 在敌方半场：你被对方抓住，你丢弃旗帜并被传送到对方的监狱

监狱位于场地边缘区域。左队监狱坐标 x: -18 到 -14, z: 26 到 30；右队监狱坐标 x: 14 到 18, z: 26 到 30。

处于寄生状态的玩家（戴着寄生头盔）不会触发抓捕判定，也无法被抓住。

### 死亡与重生

游戏开启 `doImmediateRespawn` 规则，死亡后立即重生在己方监狱区域。死亡时如果携带旗帜，旗帜会掉落。

### 装备

游戏开始时，每位玩家获得与队伍颜色相同的皮革装备：胸甲、护腿、靴子（无头盔）。所有装备附带绑定诅咒（Binding Curse），无法被取下。游戏不提供任何武器，玩家之间的战斗只能依靠抓捕机制和击退效果。

游戏开始时还会清除所有药水效果，将血量恢复至满，饱食度设为 9（不会自然回血但也不会饥饿），并关闭物品耐久消耗。

### 移动限制

- **准备阶段（PREPARING）**：玩家被限制在己方基地内（左队 x: -23 到 -21, z: -1 到 1；右队 x: 21 到 23, z: -1 到 1），无法离开
- **游戏进行中（IN_GAME）**：队伍玩家可以在整个场地内（x: -24 到 24, z: -36 到 36）自由移动，但不能离开边界。尝试越界会被传送回合法位置
- **无队伍玩家**：被强制传送到场地外围高处（y=30）俯瞰，可以飞行
- **全局限制**：所有玩家坐标被限制在 -128 到 127 的范围内

## 特殊机制

### 寄生感染

地图上会生成蠹虫（Silverfish），它们会主动追踪最近的未感染玩家。当蠹虫与玩家距离小于 0.5 格时触发感染（距离小于 2.5 格时蠹虫会主动扑向玩家，速度乘数 0.4）。被感染后立即丢弃携带的旗帜。

感染分为两个阶段，总计 260 游戏刻（约 13 秒）：

**第一阶段（0~200 tick，约 10 秒）—— 被控制**：
- 强制装备绿色皮革头盔（带绑定诅咒）
- 移动速度归零（walkSpeed = 0），无法自行移动
- 获得极高等级的跳跃提升（等级 200），用于禁止跳跃（高等级跳跃提升在 Minecraft 中会阻止玩家起跳）
- 被施加向最近的其他未感染玩家方向的推力（速度乘数 0.3）；若场地内无其他玩家则随机方向推动
- 玩家完全无法控制自身移动，只能被推力带着滑行

**第二阶段（200~260 tick，约 3 秒）—— 恢复自由**：
- 移动速度恢复正常
- 跳跃提升效果移除
- 但仍然戴着绿色头盔，视觉上仍是感染状态
- 可以自由移动

**结束后**：头盔被移除，完全恢复正常。

**传染性**：感染玩家与健康玩家距离小于 0.5 格时，健康玩家立即被感染（进入相同的两阶段流程）。**两个阶段都可以传染他人**——即使在第二阶段（自由移动阶段）仍戴着绿色头盔时接触健康玩家，也会触发传染。两个已感染玩家之间不会互相触发。

### 哞菇

地图上会生成具有自定义 AI 的哞菇（Mooshroom），随机为红色或棕色变种，随机为成年或幼年个体。它们会追踪附近的玩家（不考虑队伍归属），行为如下：

- **远距离追踪**（距离 > 5 格）：以正常速度（1.0）向玩家移动
- **冲刺**（距离 < 4 格）：切换为冲刺模式，以 3 倍速度（3.0）追击
- **冲撞**（距离 < 1 格）：给予玩家击退效果（速度乘数 0.8），随后进入冷却状态并停止冲刺
- **脱离追踪**（距离 > 5 格后）：解除冷却，恢复正常追踪

### 蜂蜜块

地图上随机生成蜂蜜块（Honey Block）集群，每半场 8 簇。每簇由 9 到 20 个蜂蜜块随机蔓延形成，作为地形障碍物减缓玩家移动速度。

### 树木和瓶子草

地图每半场随机生成 5 棵橡树（1 到 4 格高的树干加 3×3 树冠）和 5 株瓶子草（Pitcher Plant，两格高的装饰性植物）。瓶子草具有特殊效果：蠹虫进入瓶子草区域时有 50% 概率被吞噬移除（仅当地图上蠹虫总数大于 2 时触发，防止蠹虫灭绝）。

### 发光鱿鱼

场地中央水域生成 5 只发光鱿鱼（Glow Squid），作为装饰性元素。

## 机器人系统

插件内置 6 种 AI 机器人，它们以 NMS 原生玩家实体（EntityPlayer）的形式存在，不是 NPC。机器人通过模拟真实的输入来移动，触发的是真正的 `PlayerMoveEvent`，因此所有游戏机制（夺旗、抓捕、寄生等）对机器人完全一致地生效。

| 类型 | 匹配 ID | 行为 |
|------|---------|------|
| DEFAULT | `bot` | A* 寻路走向敌方旗帜，基础 AI |
| DEFAULT_JUMP | `jump-bot` | DEFAULT + 自动跳跃 + 冲刺 |
| DEFAULT_SNEAK | `sneak-bot` | DEFAULT + 始终潜行 |
| SIMPLE | `simple` | 在寻路时规避附近敌方玩家 |
| SIMPLE_JUMP | `simple-jump` | SIMPLE + 跳跃 + 冲刺 |
| TRIVIAL | `trivial` | 最强 AI：规避敌人、寄生玩家、蠹虫；攻击附近敌人 |

机器人的实现细节：

- 通过 `EntityPlayer` 创建真实的玩家实体，拥有 `GameProfile` 和网络连接
- 使用 Embedded Channel 丢弃所有下行数据包，避免不必要的网络开销
- 每个游戏刻调用 NMS 的 `aiStep()` 方法模拟玩家移动
- 支持完整的输入模拟：前后左右移动、跳跃、潜行、冲刺、攻击

## 地图生成

竞技场尺寸为 49×73 格（x: -24 到 24，z: -36 到 36），以 x=0 为中线分为左半场（红队）和右半场（蓝队）。

### 两种地图模式

- **固定地图（Fixed）**：旗帜和金块目标点按对称的固定坐标排列（x = ±22），z 轴从 6 到 34 每隔 4 格放置，共 8 对。旗帜放置在 z 负半轴，目标点放置在 z 正半轴
- **随机地图（Random）**：旗帜和目标点完全随机放置（要求 x 在 ±12 到 ±24 范围内）

### 地图元素

每半场固定包含：

- 8 面旗帜（铜块 + 栅栏 + 彩色旗帜）
- 8 个金块目标点
- 5 棵树
- 5 株瓶子草
- 与玩家数量相同的哞菇
- 与玩家数量相同的蠹虫
- 8 簇蜂蜜块

场地中央水域有 5 只发光鱿鱼。

## 游戏流程

### 1. 发起匹配

在聊天栏输入匹配命令加入等待队列：

```
match enemy:<enemy> players:<count> map:<mapType>
```

### 2. 匹配处理

系统每 2 秒（40 游戏刻）处理一次等待队列，将设置兼容的请求配对创建游戏。匹配优先级：指定对手 > 任意对手，指定地图类型 > 任意地图。

### 3. 准备阶段

游戏进入 30 秒的准备阶段（PREPARING），玩家被传送到游戏世界，游戏模式设为创造模式。玩家需要在聊天栏输入 `I'm ready!` 确认准备。所有玩家（双方均达到指定人数且全部确认）都准备好后才会开始游戏。30 秒内未能全部准备则游戏取消。

### 4. 游戏进行

游戏正式开始，时长 3 分钟。玩家切换为冒险模式，装备队伍色皮革护甲，所有 CTF 机制生效。地图在此时才重新生成（每次游戏都会重新生成地图）。

### 5. 游戏结束

宣布获胜方，展示 10 秒结果，随后玩家被传送回大厅世界，游戏世界被卸载并删除。

## 命令

### 游戏命令

| 命令 | 说明 | 权限 |
|------|------|------|
| `/ctf menu` 或 `/ctfmenu` | 打开 CTF 管理菜单 | 所有玩家 |
| `Shift + F` | 打开 CTF 管理菜单（副手交换键） | 所有玩家 |
| `/ctf watch` | 传送到当前游戏世界观战 | 所有玩家 |
| `/ctf listWorlds` | 列出当前运行中的游戏世界 | OP |
| `/ctf clearWorlds` | 清理可回收的游戏世界 | OP |

### 管理命令

| 命令 | 说明 |
|------|------|
| `/login <password>` | 管理员认证登录 |
| `/whitelist_mode [true/false]` | 切换 IP 白名单模式 |

### 聊天命令

**匹配：**
```
match enemy:<enemy> players:<count> map:<mapType>
```

参数说明：
- `enemy`：对手类型
  - `none`：无对手（练习模式）
  - `any`：任意对手
  - `bot`：DEFAULT 机器人
  - `jump-bot`：DEFAULT_JUMP 机器人
  - `sneak-bot`：DEFAULT_SNEAK 机器人
  - `simple`：SIMPLE 机器人
  - `simple-jump`：SIMPLE_JUMP 机器人
  - `trivial`：TRIVIAL 机器人
  - `<数字>`：指定 Group 编号的对手
- `players`：每队玩家人数（0 到 5）
- `map`：地图类型 `fixed` / `random` / `any`

**准备确认：**
```
I'm ready!
```

## Web 界面

插件内置 HTTP 服务器（默认端口 8001），提供以下 Web 功能：

### 3D 实时观战（Viewer3D）

基于 Three.js 的 3D 实时渲染，支持 Bloom 和 SMAA 后期处理效果。通过 SSE（Server-Sent Events）推送实时数据，使用 Zstd 压缩传输。需要登录后才能访问，且只能观战自己参与的游戏。

### 2D 小地图（Viewer2D）

简化的俯视图观战界面。

### 录像回放（Recording Replay）

在浏览器中以 3D 方式回放历史对局录像，支持速度控制和起始位置选择。

### 管理面板（Admin Panel）

REST API 接口，用于管理玩家、分组和白名单。需要管理员登录后访问。

### 统计面板（Statistics Dashboard）

基于 ECharts 的数据可视化，展示对局统计数据。

### 队伍注册（Register）

Web 端玩家注册和分组管理。

## 录像与回放

### 录制

每场对局会逐刻（tick）记录以下数据：

- 所有实体的位置、朝向、速度、装备信息
- 所有方块变化（放置、破坏、物理更新）

录制数据使用自定义二进制格式（`.dat` 文件），包含文件头（起始时间、周期、刻数）和 Zstd 压缩的数据体。

### 游戏内回放

在游戏内回放录像时，会创建一个新的维度，用僵尸实体（带自定义名称和缩小效果）代表玩家，逐刻重放所有方块和实体状态。

### Web 回放

通过 `/viewer3d/record` 接口，在浏览器中以 3D 方式回放录像，支持自定义播放速度。

## 架构

### 动态世界管理

每场游戏从模板世界（`template_world`）复制创建一个新的 Minecraft 维度。游戏结束后自动卸载并删除世界文件，避免磁盘空间浪费。

### 模块化设计

基于 TabooLib 模块系统，使用以下模块：

- **BukkitNMS**：NMS 操作，用于机器人实体创建和操控
- **BukkitUI**：菜单界面
- **BukkitNavigation**：实体寻路
- **BukkitNMSEntityAI**：自定义实体 AI
- **BukkitNMSItemTag**：物品 NBT 操作
- **BukkitUtil**：Bukkit 工具类
- **MinecraftChat**：聊天组件
- **CommandHelper**：命令系统
- **JavaScript**：脚本支持

### 依赖

- `kotlinx-serialization-json`：JSON 序列化
- `zstd-jni`：Zstd 数据压缩
- `mojang authlib`：玩家 Profile 处理

## 配置

### config.json

```json
{
  "webPort": 8001,
  "adminPassword": "password123"
}
```

- `webPort`：Web 服务器端口
- `adminPassword`：管理员登录密码

### groups.json

分组定义文件，每个分组包含 ID、名称和成员列表。

### players.json

玩家注册信息，包含玩家 ID、名称和可选的密码。

### 游戏内菜单

通过 `/ctf menu` 或 `Shift + F` 打开，可设置地图类型、玩家人数、选择队伍等游戏参数。
