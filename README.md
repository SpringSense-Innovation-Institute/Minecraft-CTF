# Minecraft-CTF

一个基于 TabooLib/Bukkit 的 Minecraft 夺旗赛插件。插件会为每场比赛复制 `template_world`
生成独立对战世界，提供游戏菜单、聊天匹配、bot 对战、2D/3D 网页观战、录像回放、队伍注册、
后台管理与统计功能。

## 运行环境

- Java 17
- Kotlin/Gradle 项目，插件版本见 `gradle.properties`
- 服务端需要提供 Bukkit/Paper/Spigot 环境；bot 代码使用 CraftBukkit `v1_21_R1` NMS
- 服务器世界目录下必须存在模板世界 `template_world`，每场比赛都会从它复制一个临时世界

首次启动后插件会在数据目录生成 `config.json`：

```json
{
  "webPort": 8001,
  "adminPassword": "password123"
}
```

`webPort` 是网页服务端口，`adminPassword` 同时用于网页管理员认证和 OP 玩家游戏内 `/login`。

## 构建

```bash
./gradlew build
```

构建产物会输出到 `build/libs`。

## 常用入口

| 入口 | 说明 |
| --- | --- |
| `http://<server>:8001/` | 网页门户 |
| `/login` | 玩家网页登录，使用后台登记的玩家 ID 和密码；密码为空时不校验 |
| `/register` | 队伍注册页 |
| `/admin` | 管理后台，使用 `config.json` 中的管理员密码 |
| `/viewer2d` | 2D 实时观战 |
| `/viewer3d` | 3D 实时观战和录像播放 |
| `/statistics` | 统计页 |
| `/ctfmenu` | 游戏内打开 CTF 菜单 |
| `/ctf menu` | 同上 |
| 潜行时交换副手 | 快捷打开 CTF 菜单 |
| `/ctf watch` | 传送到当前世界的观赛点 |
| `/ctf listWorlds` | 列出正在运行的游戏世界 |
| `/ctf clearWorlds` | 回收可回收的游戏世界 |
| `/login <password>` | OP 玩家进入服务器后需要先登录，未登录时会被拦截操作 |
| `/whitelist_mode [true\|false]` | 查看或切换插件白名单模式 |

白名单模式开启后，非 OP、非本机地址、且名字不以 `CTF-Bot-` 开头的玩家会被拒绝进入。

## 队伍与玩家

后台维护两类数据：

- 玩家：`id` 是玩家在服务器中的 Minecraft 名字，`name` 是展示名，`password` 是网页登录密码。
- 队伍：每个队伍有递增的整数 ID、队伍名和成员列表。

玩家必须属于一个队伍才能使用聊天匹配。玩家进入服务器时，插件会按队伍名给玩家设置计分板前缀。

## 开始比赛

### 方式一：聊天匹配

在主世界聊天发送：

```text
match enemy:<enemy> players:<count> map:<mapType>
```

参数：

- `enemy:none`：无对手练习。
- `enemy:any`：匹配任意可用对手。
- `enemy:<groupId>`：指定另一个玩家队伍 ID。
- `enemy:bot`、`jump-bot`、`sneak-bot`、`simple`、`simple-jump`、`trivial`：指定 bot 对手。
- `players:<count>`：每队人数；聊天匹配接受 `0..5`，实际比赛通常使用 `1..5`。
- `map:fixed`：固定旗帜和目标点布局。
- `map:random`：随机旗帜和目标点布局。
- `map:any`：任意地图类型。

匹配队列每 40 tick 处理一次。插件会优先尝试加入符合条件、仍在准备阶段的现有比赛；否则会把
条件兼容的两个队伍配成一场新比赛。指定 `none` 或 bot 时会直接创建自用比赛，bot 会自动加入并准备。

### 方式二：管理员菜单

OP 在主世界打开 CTF 菜单，可以设置红队、蓝队、每队人数、地图类型，并创建比赛世界。管理员创建的
比赛不会因为 30 秒准备超时自动取消。

管理员也可以启用练习赛模式。练习赛模式可以限制匹配对手、地图类型和每队人数，并把录像和统计记录
归到练习赛名称下。

## 准备阶段

- 玩家加入比赛世界后会收到 `Are you ready?`。
- 参赛玩家在聊天中发送 `I'm ready!`，大小写不敏感，即可标记准备。
- 双方非空队伍都必须达到设置人数，并且所有参赛玩家都准备后，比赛才会开始。
- 聊天匹配创建的常规比赛有 600 tick，也就是 30 秒准备时间；未满员或未全员准备会结束该局。
- 准备阶段红队只能待在左侧基地，蓝队只能待在右侧基地；非参赛者会被限制在场外观战位置。

## 场地与阵营

- 场地区域是 `x=-24..24`、`z=-36..36`、`y=-64..12`。
- 左半场是 `x=-24..-1`，右半场是 `x=1..24`，中线是 `x=0`。
- 红队是左队，出生/准备基地在左侧，穿红色绑定诅咒皮革甲，守红旗，抢蓝旗。
- 蓝队是右队，出生/准备基地在右侧，穿蓝色绑定诅咒皮革甲，守蓝旗，抢红旗。
- 被抓、死亡或重新进入进行中的比赛时，玩家会回到自己队伍的 prison 点；prison 是复位点，不是永久牢房。
- 非参赛者在进行中或准备中的比赛世界会处于创造模式，并被限制在场外。

世界外层还有一个通用边界：玩家坐标超出 `x=-128..127` 或 `z=-128..127` 会被拉回边界内。

## 地图生成

每局开始时会清空并重新生成地图。

固定地图：

- 每队 8 面旗。
- 红旗在左半场 `x=-22`、负 `z` 方向。
- 蓝旗在右半场 `x=22`、负 `z` 方向。
- 每队 8 个金块目标点在己方半场正 `z` 方向。

随机地图：

- 每队 8 面旗和 8 个金块目标点。
- 左侧旗和目标点随机落在 `x=-24..-12`。
- 右侧旗和目标点随机落在 `x=12..24`。
- 只会放在地面为草方块、上方两格为空的位置，且不会互相重叠。

无论固定还是随机地图，都会额外生成：

- 10 棵树。
- 10 株瓶子草。
- 哞菇总数为每队人数的 2 倍。
- 蠹虫总数为每队人数的 2 倍。
- 5 只发光鱿鱼。
- 16 片蜂蜜块区域，每片会随机扩散若干格。

## 夺旗与得分规则

目标是在 3 分钟内把更多敌方旗帜带回己方金块目标点。

1. 玩家靠近敌方旗帜底座即可捡旗。旗帜底座由蜡铜块、橡木栅栏和旗帜组成。
2. 捡起旗帜后，敌方旗帜会戴在玩家头上。
3. 携带旗帜的玩家进入己方半场，站到空的金块目标点上，即可插旗得分。
4. 已经插到金块目标点上的旗帜会永久计分，不能再被捡走。
5. 玩家死亡、被抓或被蠹虫寄生时，如果身上有旗，旗会掉落到附近可用草地方块上。
6. 掉落旗不会自动回到原位；仍然需要进攻方重新捡起并送到目标点。

每队最多 8 分。红队得分计为蓝旗被插到金块目标点的数量，蓝队得分计为红旗被插到金块目标点的数量。

## 抓人与战斗

- 比赛开始后 PvP 开启，玩家处于冒险模式。
- 参赛玩家接触敌人时会触发抓人判定，不需要挥拳。
- 如果双方都在红队半场，红队玩家可以抓蓝队玩家。
- 如果双方都在蓝队半场，蓝队玩家可以抓红队玩家。
- 被抓者会掉旗并传送回自己的 prison 点。
- 被蠹虫寄生中的玩家不会触发抓人判定，也不会被抓人判定处理。
- 玩家死亡后会立即重生，掉旗并回到自己的 prison 点。

插件会取消方块破坏、方块放置、物品掉落和多数交互，所以比赛主要依靠移动、路线选择、身体接触、
PvP 和地图生物机制进行。

## 生物与特殊机制

### 哞菇

哞菇会追逐最近的参赛玩家。靠近玩家时会加速冲刺，并在贴近时把自己推向玩家，形成干扰。

### 蠹虫

蠹虫会追逐最近的未寄生参赛玩家。进入瓶子草时，若场上蠹虫数量大于 2，有 50% 概率消失。
蠹虫靠近玩家时会扑向玩家，距离足够近会触发寄生。

### 寄生

被寄生的玩家会立刻掉旗，并戴上绿色绑定诅咒皮革头盔。

- 前 200 tick，约 10 秒：玩家速度被设为 0，并被持续推向最近的其他参赛玩家；没有目标时会随机移动。
- 第 200 到 260 tick，约 3 秒：玩家恢复移动，但仍处于寄生状态。
- 到 260 tick 后：寄生头盔移除，状态结束。
- 寄生状态会通过接触传播给任何未寄生玩家，包括队友和敌人。

## 胜负判定

比赛每 tick 检查一次胜负。

- 任意一队先达到 8 分，立即获胜。
- 如果两队同时达到 8 分，判为平局。
- 3 分钟到时，得分更高的一方获胜。
- 3 分钟到时双方同分，判为平局。
- 如果某个非空队伍在比赛世界中的在线人数为 0，另一队获胜。
- 如果双方非空队伍都无人在线，判为平局。

比赛结束后：

- 所有玩家切回创造模式。
- 参赛者收到 `Game over!`。
- 玩家背包清空。
- OP 会看到录像文件名提示。
- 世界空闲后会被回收并删除临时世界目录。

## 录像、观战与统计

- 每局比赛都会记录地图内方块变化和实体状态，录像文件保存在插件数据目录的 `records` 下。
- 游戏内菜单可以播放录像；`/viewer3d` 也能读取录像列表并播放网页 3D 回放。
- `/viewer2d` 和 `/viewer3d` 的实时观战需要玩家先通过 `/login` 网页登录。
- 统计数据保存在插件数据目录的 `statistics` 下。
- 统计项包括对战类型次数、抓人次数、夺旗次数、总时长和胜场等。
- 抓人、夺旗、胜场和总时长等 PvP 统计只在双方都是玩家队伍时完整记录。

## 其他机制

- 玩家加入服务器会被清空背包、切到创造模式并传送回主世界中心附近。
- 主世界中如果玩家手持名称包含 `文明终点：黑曜石` 的物品，插件会清空其背包并向主世界玩家公告。
- 插件关闭时会踢出在线玩家，卸载并删除所有临时游戏世界，停止网页服务。

## 实现说明

- `MinecraftCtf.kt`：插件启动、配置、匹配定时任务和网页服务启动。
- `GameManager.kt`：匹配队列、创建玩家局、bot 局和无对手练习局。
- `GameWorld.kt`：准备、开赛、结束、胜负判定、地图状态和录像生命周期。
- `GameListeners.kt`：捡旗、插旗、抓人、死亡掉旗、寄生、聊天准备等核心规则。
- `Listeners.kt`：世界边界、菜单快捷键、聊天匹配、聊天转发和通用事件限制。
- `MapGeneration.kt`：旗帜、目标点、障碍、生物和蜂蜜块生成。
- `bot/`：假玩家创建和 bot 行为。
- `web/`：门户、登录、注册、管理、统计、2D/3D 观战和录像接口。
